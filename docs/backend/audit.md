# Audit / Approval API (generic module) API

稽核模組是一套與具體業務實體無關的通用審核機制：任何「被稽核」的異動送出後不會立即套用，而是先建立一筆待審請求，唯有在審核人員核准後才會真正套用到目標資料；查詢一律讀取目前生效（已核准）的資料，不受待審請求影響。本模組不認識任何業務實體的欄位或規則，實體專屬的再驗證與實際套用邏輯，全部委由各業務主題自行註冊的處理邏輯執行。核准/駁回/取消三個動作本身則是立即生效的操作：核准會馬上觸發目標的真正異動，駁回與取消則立即將請求標記為終態、不異動任何目標資料。

## 欄位定義

**AuditRequest（審核請求）**

| Field | Type/Role | Rule |
|---|---|---|
| id | 識別碼 | 系統主鍵 |
| entityType | 標的類型 | 由送審端指定的字串（如 CURRENCY_PAIR、BRAND_SPREAD、SPREAD_GROUP、SPREAD_GROUP_MEMBER），本模組視為不透明值 |
| actionType | 異動類型 | CREATE、UPDATE 或 DELETE |
| entityId | 標的識別碼 | 新增類型時為空；其餘情況即為目標的識別鍵，是「同一標的僅能有一筆待審」規則的判斷依據 |
| brandId | 所屬品牌 | 供依品牌篩選／顯示使用，非品牌相關的異動可為空 |
| summary | 摘要說明 | 一行式人類可讀描述，長度上限 200 字 |
| beforeData | 異動前快照 | 新增類型時為空，其餘情況為送出當下目標的現有資料 |
| afterData | 異動後快照 | 刪除類型時為空，其餘情況為請求的新值 |
| status | 審核狀態 | 起始為待審中，可轉為已核准／已駁回／已取消；離開待審中後即為終態，不可再變更 |
| requestedBy / requestedAt | 提交人／提交時間 | 提交人為呼叫端自行提供的字串（未提供時預設為 system） |
| reviewedBy / reviewedAt | 審核人／審核時間 | 待審期間皆為空 |
| reviewComment | 審核意見 | 駁回時必填（1–500 字），核准時選填 |
| applyError | 套用失敗原因 | 核准時若套用失敗會記錄原因，正常情況下為空 |

## 限制條件
- 同一標的（標的類型＋標的識別碼）同時只能有一筆待審請求，違反時視為衝突（409），由服務邏輯與資料庫唯一鍵雙重把關。
- 請求一旦離開待審中（核准／駁回／取消）即為終態，不可再變更；對已終態請求執行核准／駁回／取消一律視為衝突（409）。
- 每筆異動在送出時與核准時都會各驗證一次：送出時擋下明顯不合法的請求，核准時再以「當下最新資料」重新確認是否仍然合法，避免套用已過時、與現況衝突的異動。
- 找不到對應標的類型可處理的審核邏輯，視為系統設定錯誤（伺服器錯誤，500），非使用者操作可觸發。
- 核准套用時若因資料已變動而失敗，請求維持待審中並記錄失敗原因，不會自動轉為駁回，等問題排除後可重試，也可由提交者取消。
- 駁回時必須填寫理由（1–500 字），未填寫視為請求格式錯誤（400）。
- 取消僅能作用於待審中的請求，用途是讓提交者收回自己不再需要的請求，不會套用任何異動到目標資料。
- 核准動作中的再驗證、實際套用與狀態更新視為同一個不可分割的操作，任一步驟失敗則全部復原，不會留下半套用的狀態。

## 跨主題規則
- 本模組不驗證、不解讀任何業務實體自己的欄位規則；所有標的專屬的再驗證邏輯與實際套用動作，都由各業務主題自行註冊、各自實作（見 currency-pair.md、spread.md）。
- 提交人／審核人（requestedBy／reviewedBy）僅為呼叫端自行提供的字串，本專案目前沒有身分驗證機制，因此無法防止同一人自己核准自己送出的請求——這是屬性標記而非安全控管，各業務主題呼叫本模組送審時皆沿用此同一套機制（見 currency-pair.md、spread.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/audit-requests | 查詢待審／已審核請求清單，可依狀態、標的類型、品牌、標的識別碼篩選 | Live direct |
| GET | /api/audit-requests/{id} | 查詢單筆審核請求詳情，含異動前後快照 | Live direct |
| POST | /api/audit-requests/{id}/approve | 核准一筆待審請求，立即重新驗證並套用異動到目標資料 | Direct |
| POST | /api/audit-requests/{id}/reject | 駁回一筆待審請求，立即標記為終態，不套用任何異動 | Direct |
| POST | /api/audit-requests/{id}/cancel | 由提交者撤回一筆待審請求，立即標記為終態，不套用任何異動 | Direct |
